### A2. Make `softwareVersion` dynamic

**File:** `site/.vitepress/config.mts`

**Change:** Read version from `package.json` instead of hardcoding.

**Implementation notes:**
- `config.mts` is at `site/.vitepress/`, so `package.json` is at `../../package.json`.
- The `import ... assert { type: 'json' }` syntax is deprecated/version-sensitive. Prefer Vite's
  native JSON import (no assertion) or a build-time constant to avoid bundler issues:

```typescript
// Preferred: Vite handles JSON imports natively in config files
import packageJson from '../../package.json'

// In transformHead:
softwareVersion: (packageJson as { version?: string }).version || '1.0.0-beta.2',
```

### B4. Add `WebSite` JSON-LD with `SearchAction` — **SKIPPED** ✅

**Status:** Skipped on 2026-09-15. VitePress local search is a client-side overlay (MiniSearch
index in the JS bundle) and does not render results from a URL like `?q=ffmpeg`. There is no
server-rendered search-results page, so a `SearchAction` `target` would point at a URL that does
not actually search. Google has also de-emphasized sitelinks searchbox markup. Revisit only if a
real search-results page is ever built.

- **Thin content:** Each new page must have 500+ words of unique, useful content

- **Keyword cannibalization:** Follow existing guardrails in `SEO_KEYWORD_OPTIMIZATION_PLAN.md`

- **Build failures:** Test each checkpoint before proceeding
- **Translated schema accuracy:** Verify translated FAQ/HowTo/Breadcrumb content matches the translated Markdown on each locale page
- **Incomplete locale FAQ coverage:** Some locale pages are missing FAQ sections — these must be added before the translated schema can be generated for those pages
- **Translation quality:** Ensure translated schema content is natural and accurate (not machine-translated gibberish)

# Testing

## Commands

```bash
# Run all tests
npm test

# Watch mode
npm run test:watch

# With coverage report
npm run test:coverage

# Unit tests only
npm run test:unit

# Integration tests (matches src/**/*.integration.{test,spec}.{ts,tsx})
npm run test:integration

# E2E tests (requires build)
npm run test:e2e

# MCP end-to-end tests
npm run test:e2e:mcp

# Performance suites
npm run perf
```

Coverage reports are generated in `coverage/`:

- `coverage/index.html` — browsable HTML
- `coverage/lcov.info` — LCOV for IDE integration

## Test Setup

The test environment (`src/test-setup.ts`) provides:

- Mocked `useTranslation` from `react-i18next` with English key mapping and interpolation
- Mocked `electronAPI` on `globalThis` covering all IPC methods
- Registers `@testing-library/jest-dom/vitest` matchers

## E2E Tests

End-to-end tests live in `e2e/` (Vitest with the node environment, 60s timeouts) and are gated behind the `E2E` env var or CI. There are 31 specs in `e2e/specs/`, 6 in `e2e/mcp/`, the root CLI spec, and one boot-budget fixture test:

| File(s)            | What's Covered                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------- |
| `e2e/cli.spec.ts`  | CLI mode: `--help`/`-h`, subcommands (`convert`, `info`, `capabilities`, `compress`, `extract-audio`, `batch`, `remux`, `demux`), legacy flat syntax, global flags (`--quiet`, `--no-color`, `--theme`) |
| `e2e/specs/shell`, `dashboard`, `about`, `navigation-drawer`, `language`, `keyboard-shortcuts` | App shell: window title, `electronAPI` presence, all nav routes, drawer navigation, window controls, language menu, shortcuts |
| `e2e/specs/convert`, `remux-demux-filters`, `profiles` | Media conversion, remux/demux planning, video filters, and profile selection |
| `e2e/specs/batch`, `audio-extract`, `image-compress`, `media-info`, `video-cut`, `logs` | Main tool pages: queue, audio/image/video workflows, probing, and the log viewer |
| `e2e/specs/copilot`, `copilot-saved-chats` | Copilot planning and saved conversations |
| `e2e/specs/settings`, `settings-ai`, `settings-mcp`, `terms-gate` | Settings, AI and MCP configuration, telemetry consent, Terms gate |
| `e2e/specs/a11y`, `focus-order`, `error-states`, `ipc-abuse`, `ipc-events`, `hostile-bridge`, `cli-hostile`, `harness-recovery`, `boot-budget` | Accessibility, focus order, error states, hostile IPC/bridge input, recovery, and startup budget |
| `e2e/specs/real-convert.spec.ts` | Tier B (real): actual FFmpeg conversion without mocks (gated behind `E2E_REAL=1`) |
| `e2e/mcp/*.spec.ts` | MCP end-to-end: stdio, standalone HTTP, embedded GUI, MCP Apps, and VS Code client/UI |

## Performance Suites

`perf/` holds 11 `*.perf.test.ts` suites (startup, queue concurrency, IPC overhead, large files, extraction, memory leaks, process lifecycle, conversion benchmark, CLI batch, and phase-8 I/O/queue) plus shared `test-utils.ts`. Run them with `npm run perf`.

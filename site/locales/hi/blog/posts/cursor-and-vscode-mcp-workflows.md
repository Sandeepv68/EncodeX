# Cursor और VS Code में EncodeX MCP वर्कफ़्लो

Cursor और VS Code दोनों MCP बोलते हैं, जिसका मतलब है कि आप अपने कोड से बाहर निकले बिना मीडिया काम अपने एडिटर की AI को सौंप सकते हैं। दोनों में से किसी एक को EncodeX के बिल्ट-इन सर्वर की ओर इंगित कीजिए और कन्वर्जन, ऑडियो एक्सट्रैक्शन या पूरे इमेज फ़ोल्डर का कंप्रेशन माँगिए, जबकि आप असली प्रोजेक्ट पर काम करते रहें।

सर्वर लोकली चलता है (`encodex --mcp`), इसलिए एडिटर का एजेंट आपकी मशीन के अपने FFmpeg इंजन को चलाता है — कोई अपलोड नहीं, कोई बाहरी API नहीं, पूरी तरह ऑफ़लाइन।

## VS Code में EncodeX सेटअप करें

VS Code में बिल्ट-इन MCP सपोर्ट है। MCP सेटिंग्स खोलकर एक सर्वर परिभाषा जोड़िए:

```json
{
  "mcpServers": {
    "encodex": {
      "command": "encodex",
      "args": ["--mcp"]
    }
  }
}
```

VS Code `encodex --mcp` को सर्वर प्रोसेस के रूप में चलाता है। जुड़ने के बाद, एडिटर का असिस्टेंट EncodeX के टूल कॉल कर सकता है — `convert_media`, `extract_audio`, `compress_image`, `cut_video`, `batch_convert` — और जॉब `get_job` / `list_jobs` से ट्रैक कर सकता है।

अतिरिक्त लाइव टूल (कतार स्थिति, टाइमलाइन, प्रीव्यू, सिस्टम जानकारी) के लिए EncodeX GUI में **Settings → MCP Server** चालू करें और एडिटर को `http://127.0.0.1:8765/mcp` पर इंगित करें। वह सतह `get_queue_state`, `extract_preview` और `get_timeline` जैसे GUI-समकक्ष टूल जोड़ती है।

## Cursor में EncodeX सेटअप करें

Cursor भी अपनी सेटिंग्स में MCP सर्वर देता है — या तो वही JSON, या `command` प्रकार के साथ कोई समान "MCP सर्वर जोड़ें" संवाद:

- **कमांड (stdio):** `encodex --mcp`

Cursor मानक MCP कॉन्फ़िगरेशन प्रारूप साझा करता है, इसलिए ऊपर वाला JSON ब्लॉक Cursor के लिए भी काम करता है। सर्वर जोड़ने के बाद Cursor का एजेंट सीधे मीडिया ऑपरेशन कर सकता है।

## एडिटिंग वर्कफ़्लो

उपयोगी पैटर्न मीडिया काम को अपने एडिटर के सामान्य प्रवाह के साथ जोड़ना है:

> `assets/tmp/video.mov` को डॉक्स पेज के लिए MP4 में बदलिए, `assets/` फ़ोल्डर में।

एजेंट `convert_media` कॉल करता है, `get_job` का इंतज़ार करता है, और फिर आगे का काम करता है — प्रीव्यू होस्ट करना, README अपडेट करना या नई फ़ाइल को बिल्ड से जोड़ना।

और उन्नत: एक प्रॉम्प्ट कई कदम तय कर सकता है:

> `~/r2d2/captures` में नई रिकॉर्डिंग आ गई है। इसे कंप्रेस्ड MP4 में बदलिए, ट्रांसक्रिप्शन के लिए ऑडियो निकालिए, और फिर `docs/captures.md` को आउटपुट स्थानों के साथ अपडेट कीजिए।

यानी `convert_media` + `extract_audio`, एक ही सेशन में आपके रिपॉज़िटरी काम के साथ समन्वित।

## वर्ज़न किया हुआ आउटपुट और सफ़ाई

चूँकि EncodeX डिस्क पर वास्तविक फ़ाइलें बनाता है, आप इसे अपने git वर्कफ़्लो से जोड़ सकते हैं:

> `~/r2d2/captures` से `~/r2d2/output` तक का बैच चलाइए, फिर बताइए कि कौन-सी आउटपुट फ़ाइलें नई हैं ताकि मुझे पता चले क्या जोड़ना है।

एजेंट टूल के नतीजे, `list_jobs` इतिहास और आपकी डायरेक्टरी की स्थिति पढ़कर सारांश देता है कि क्या बदला — एक मीडिया काम को दस्तावेज़ित कमिट में बदल देता है।

## अक्सर पूछे जाने वाले प्रश्न

### क्या यह मेरा कोड या मीडिया क्लाउड में भेजता है?

नहीं। EncodeX MCP पूरी तरह आपकी मशीन पर चलता है। आपका मीडिया लोकली प्रोसेस होता है और आपके एडिटर का एजेंट उन लोकल टूलों को चलाता है। एन्कोडिंग के लिए कोई क्लाउड राउंड-ट्रिप नहीं है।

### क्या EncodeX GUI खुला होना ज़रूरी है?

stdio सर्वर (`encodex --mcp`) के लिए नहीं — वह बिना GUI के चलता है। एम्बेडेड HTTP सर्वर वैकल्पिक सतह है जो ऐप में चलती है और लाइव कतार व प्रीव्यू टूल जोड़ती है।

### क्या इसे Cursor और VS Code के साथ एक साथ उपयोग कर सकते हैं?

हाँ। हर क्लाइंट अपना stdio सर्वर इंस्टेंस चलाता है, या आप दोनों के लिए एक ही एम्बेडेड HTTP एंडपॉइंट साझा कर सकते हैं (गया GUI इंस्टेंस)।

### कौन-से टूल उपलब्ध हैं?

stdio सतह 13 मुख्य टूल देती है जिनमें `convert_media`, `batch_convert`, `extract_audio`, `compress_image`, `cut_video` और जॉब प्रबंधन शामिल हैं। पूरा कैटलॉग [फ़ीचर रेफ़रेंस](/hi/docs/features-reference#mcp-server) में पढ़ें।

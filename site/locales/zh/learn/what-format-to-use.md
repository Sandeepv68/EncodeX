# 该选择什么视频格式？

**简短回答：** 如果你只想要一个"在哪都能播放"的文件——手机、电视、笔记本或发给别人——就用 **MP4 + H.264**（AAC 音频）。世界上几乎所有设备和平台都能读取它。

下面这些内容，是给那些不只是"帮我播放一下"的场景准备的。

## 快速决策表

| 你的目标 | 最佳格式 |
|------------------------|------------------|
| 尽可能到处播放 | MP4 / H.264 |
| 让文件更小 | H.265 / HEVC |
| 上传到网页 | WebM / VP9 |
| 专业剪辑 | ProRes |
| 无损归档 | FFV1 / MKV |
| 用邮件发送 | 小体积 MP4 |
| 提取音乐 | MP3 / AAC |
| 保持流不变 | 重新封装（MP4↔MKV） |

## 尽可能到处播放 → MP4 / H.264

MP4 是通用容器，H.264 是其中兼容性最好的编码。如果有人给你一个文件说"麻烦让它能播放"，就用这个组合。

- **用于：** 手机传输、邮件附件、社交平台上传、与家人分享。
- **为什么：** 所有手机、电视、浏览器和剪辑软件的硬件解码都支持 H.264。

## 让文件更小 → H.265 / HEVC（或 AV1）

想要每 MB 有最好的画质，就用更新的编码：

- **H.265 / HEVC** — 相同画质下体积约为 H.264 的一半。非常适合归档 4K 或精简片库。对旧设备的兼容性稍差。
- **AV1** — 最新选择，文件更小，但编码更慢，且只有较新设备有硬件支持。

两者都保留 MP4 容器，所以文件如今几乎随处可播。

## 上传到网页 → WebM / VP9

对于网站，尤其是你自己控制播放器时（自建站、博客、演示），WebM + VP9 是可靠选择：开源、画质高、同等画质下比 H.264 更小。它并非所有设备都能播，但所有现代浏览器都支持。

## 专业剪辑 → ProRes

当你在 Final Cut、Premiere、Resolve 里剪辑时，中间编码比文件大小更重要。**ProRes 422** 针对流畅的时间线预览和多次剪辑无画质损失做了优化，定稿后再转成 MP4/H.264 交付。

## 无损归档 → FFV1 / MKV

长期归档通常需要无损：**FFV1** 是档案工作者最爱（许多数字保存项目都在用），通常放在 **MKV** 容器里。画质与源完全一致，代价是文件很大。

## 邮件发送 → 小体积 MP4

邮件仍然拒绝超过约 25 MB 的文件。你的真正目标不是"格式"，而是**体积**。转成 H.264/MP4 后降低分辨率或码率直到能发送，或用按目标体积压缩的工具。

## 提取音乐 → MP3 / AAC / FLAC

如果你根本不需要视频，只提取音轨即可。**MP3** 和 **AAC** 是日常选择；想要无损就用 **FLAC**。

## 保持流不变 → 重新封装（MP4↔MKV）

有时文件已经很好了——你只是想要另一种容器。**重新封装（Remux）**会直接复制视频和音频流而不重新编码，瞬间完成、画质无损、体积几乎不变。

## 常见问题

### 哪种视频格式兼容性最好？

**MP4 + H.264 视频 + AAC 音频**是最安全的通用选择——所有手机、电视、浏览器和剪辑应用都支持。

### MKV 比 MP4 好吗？

MKV 能容纳更多流类型以及额外的音轨、字幕轨，但 MP4 在兼容性上更胜一筹。如果 MKV 在你需要的所有地方都能播放，就保留它；否则重新封装或转成 MP4。

### H.265 会比 H.264 画质损失更大吗？

不会——在**相同文件大小**下，H.265 通常明显更好。代价是对旧硬件兼容性稍差、编码时间更长。

### 应该用 AV1 还是 HEVC？

AV1 文件更小，但编码更慢，且需要较新的硬件播放。对今天大多数人来说，HEVC 是更务实的选择。

### 为什么我的视频邮件发不出去？

因为它只为画质编码，没考虑体积。按大小限制（通常 25 MB）重编码为 MP4/H.264、降低分辨率，或用按体积压缩的工具。

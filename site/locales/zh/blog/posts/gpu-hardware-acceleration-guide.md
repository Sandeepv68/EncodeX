# 什么是硬件加速？它为何能让你的视频编码更快？

当你转换视频时，每一帧都必须重新编码——这需要算力。一个 1080p、十分钟的片段大约有 18,000 帧，每一帧都要处理和压缩。在现代 CPU 上，这一过程没有问题，但很耗时：一个五分钟的视频可能需要几分钟才能转换完成。硬件加速则彻底改变了局面——它把这部分工作从 CPU 转移到了 GPU。

## CPU 编码 vs GPU 编码：有什么区别？

CPU 是一个通用处理器。它什么都很擅长——运行操作系统、处理浏览器标签页、管理下载。但它并非为视频编码专门设计。它使用固定数量的强大核心，每个核心一次只执行一个任务。

而 GPU 则拥有成百上千个小型核心，专为一件事而设计：在海量数据上同时执行同一个简单计算。视频编码正是这类工作负载——每一帧都用几乎相同的操作处理，因此 GPU 能并行处理大量帧。

结果就是编码更快。具体快多少取决于视频、GPU 和编码器，但硬件加速编码通常比纯 CPU 编码**快三到十倍**。一个在 CPU 上需要八分钟才能转换完成的视频，在 GPU 上可能不到一分钟就能完成。

## 你会看到的硬件编码器

每一家主流 GPU 厂商都在自己的芯片中内置了视频编码器。EncodeX 会自动检测并启用你系统中现有的那一个：

- **NVENC**（NVIDIA）：自 2012 年起内置在 GeForce 和 Quadro GPU 中。支持 H.264、H.265 和 AV1。NVENC 被广泛认为是单位比特画质最佳的硬件编码器，尤其在 RTX 系列显卡上。

- **QSV（Quick Sync Video）**（Intel）：内置在 Intel 集成显卡中。支持 H.264、H.265 和 AV1。在以 Intel 核显为主要 GPU 的笔记本电脑上尤其高效。

- **AMF（Advanced Media Framework）**（AMD）：内置在 Radeon GPU 中。在较新型号上支持 H.264、H.265 和 AV1。在基于 RDNA 架构的新款 GPU 上可与 NVENC 一较高下。

- **VAAPI**（Video Acceleration API）：Linux 的硬件加速层。通过 VA-API 驱动支持 NVIDIA、Intel 和 AMD GPU。是大多数 Linux 桌面端的标准路径。

- **VideoToolbox**（Apple）：macOS 的内置硬件编码。支持 H.264 和 HEVC。在 Apple Silicon（M1–M4）上极其高效，因为编码器和解码器与 CPU 位于同一颗芯片上。

## 何时使用硬件加速

以下情况最适合使用硬件加速：

- 你在转换视频用于分享（社交媒体、邮件、聊天软件），此时速度比压榨最后几个百分点的画质更重要。
- 你要批量转换大量文件，希望更早完成。
- 你的源文件很大（4K、高码率），编码工作量相当可观。

以下情况可能不适合使用硬件加速：

- 你需要绝对最高的每 MB 压缩率（用于存档）。使用慢速预设的 CPU 编码器往往能在相同画质下生成略小的文件。
- 你在使用没有现代编码器的老旧 GPU。

对大多数人来说——分享视频、压缩上传、剪辑转换片段——硬件加速都是正确的选择。在常见的观看尺寸下，画质差异几乎无法察觉，而速度提升却是实实在在的。

## 画质呢？

硬件编码的视频画质非常好——在常见的观看尺寸下接近 CPU 编码的水准。主要差异出现在极低的码率下，或是逐帧分析时，这关乎视频编辑者和档案管理员，但对大多数观众来说并不重要。

对于日常分享——YouTube、Instagram、给朋友发个片段——你看不出区别。文件会小得多，编码也会快得多。
